## 1. 这是什么

一个跑在**边缘计算平台**上的自建 CDN 网关。你把域名解析过来，它负责：

- **反向代理回源**：把用户请求转发到你的真实源站（对象存储、VPS、任意 HTTP 服务）
- **多源站负载均衡**：链式回退 / 轮询 / 加权 / 随机 / IP 哈希
- **边缘缓存**：让静态资源命中边缘节点，用户就近读取
- **规则引擎**：按路径、请求头、地区等条件改写请求、改写响应、重定向
- **安全防护**：防盗链、UA/IP 黑白名单、签名 URL、限流
- **可视化管理面**：网页里点点点就能配好上面所有能力，无需改代码

**一句话**：用 Cloudflare / EdgeOne 的免费边缘额度，搭一个你自己完全可控的 CDN。

---

## 2. 它不是什么（先对齐预期，避免误解）

| 误解 | 实际情况 |
|---|---|
| 「它自带硬盘存储缓存文件」 | ❌ 本项目**自身无持久存储**。缓存完全依赖底层边缘平台，代码只负责下发正确的缓存头 |
| 「装上就能加速任何网站」 | ❌ 你必须有一个**自己的源站**，并且把域名解析到边缘平台 |
| 「配置存在本地文件里」 | ❌ 配置存在平台的 **KV 存储**里，所以 `CDN_KV` 绑定是必做项 |

## 3. 三种部署形态，怎么选

核心代码三者**完全一致**，只是入口薄壳和平台能力不同。

| 形态 | 适合谁 | 优点 | 限制 |
|---|---|---|---|
| **Cloudflare Workers** | 想要功能最全 | 支持 TCP socket 回源（**裸 IP + 自定义 Host**）、支持 R2 直连回源 | 需要 Cloudflare 账号 |
| **Cloudflare Pages** | 想用 Git 推送自动构建 | 绑定/域名全在控制台点，无需命令行 | 无 socket，只能域名源站 |
| **EdgeOne Pages** | 业务在国内、需要国内节点 | 国内边缘节点、访问快 | 无 D1、无 socket、无 R2 |

**选不出来就按这个来：**

```
需要国内访问速度？ ── 是 ──→ EdgeOne Pages
        │
        否
        ↓
需要裸 IP 回源 / R2 直连？ ── 是 ──→ Cloudflare Workers
        │
        否
        ↓
    Cloudflare Pages（最省心）
```

> 三种形态的能力差异在管理面「系统信息」页可实时查看（`hasSocket` / `hasD1` / `hasKV` 等）。

## 4. 整体架构（一张图看懂）

```
                    用户请求
                       │
                       ▼
        ┌──────────────────────────────┐
        │   边缘平台（CF / EO）          │
        │                              │
        │  /{ADMIN_PATH}/assets/*      │──→ 静态托管（零函数调用）
        │                              │
        │  其余所有请求                  │──→ _worker.js
        └──────────────────────────────┘         │
                                                 ▼
                          ┌──────────────────────────────────┐
                          │ /{ADMIN_PATH}/api/*  → 管理 API   │──→ KV（读写配置）
                          │ /{ADMIN_PATH}        → 管理面 HTML │
                          │ 其余                  → 数据面代理  │
                          └──────────────────────────────────┘
                                                 │
                                                 ▼
                                        你的真实源站
```

**关键概念（后面反复出现，先记住）：**

| 概念 | 含义 |
|---|---|
| `_worker.js` | 构建产物，所有逻辑打包进这一个文件。**不要手动编辑** |
| `ADMIN_PATH` | 管理面的路径前缀，默认 `__panel`，建议改成随机串当第一层防护 |
| `CDN_KV` | KV 绑定的**变量名**，必须叫这个，网关按此名探测配置存储 |
| 源站（Origin） | 你的真实后端地址 |
| 源站池（Pool） | 多个源站 + 负载均衡策略，可被多个站点共享 |
| 站点（Site） | 一个加速域名，引用一个源站池 |

## 5. 仓库结构速览

```
├── src/              源码（构建的输入，改逻辑改这里）
├── web/              管理面前端（HTML/CSS/JS）
├── build.mjs         构建脚本：src/ + web/ → _worker.js + dist/public/
├── _worker.js        构建产物（已提交到仓库，供平台直接读取）
├── dist/public/      管理面静态资源产物
├── edge-functions/   EdgeOne / CF Pages 的入口薄壳
├── wrangler.toml     Cloudflare 部署配置
├── edgeone.json      EdgeOne 部署配置
└── docs/             本文档
```
