## 0. 核心概念一图流（先看这个）

不管你多小白，记住**四个积木**就够：

```
┌─────────────┐     ① 一个域名一个站点      ┌──────────────────┐
│  访问者      │ ─────────────────────────►  │  站点 Site        │
│ (浏览器/App) │      img.example.com         │  （加速域名）      │
└─────────────┘                              └────────┬─────────┘
                                                     │ ② 站点决定"去哪取数据"
                                                     ▼
                                          ┌──────────────────┐
                                          │  源站组 Pool       │
                                          │ （一组可互换的源站） │
                                          │ 策略: chain/加权…  │
                                          └────────┬─────────┘
                                                   │ ③ 池里挑一个源站
                          ┌────────────────────────┼────────────────────────┐
                          ▼                        ▼                        ▼
                    ┌──────────┐            ┌──────────┐            ┌──────────┐
                    │ 源站 A    │            │ 源站 B    │            │ 源站 C    │
                    │(主)      │            │(备)      │            │(备)      │
                    └──────────┘            └──────────┘            └──────────┘

  ④ 规则 Rules：挂在站点下，决定"/images/* 走源站组X、/api/* 回 503、带 bot UA 拦截"
```

| 积木 | 一句话 | 必填？ | 能复用吗 |
|---|---|---|---|
| **站点 Site** | 一个加速域名（如 `img.example.com`） | 必填（你至少要有一个域名） | 每个域名一个，不共用 |
| **源站组 Pool** | 一组能互相顶替的源站 + 调度策略 | 可选（也可直接在站点里填源站） | ✅ 多个站点可共用同一个池 |
| **源站 Origin** | 你的真实服务器地址（域名/IP + 端口 + 协议） | 必填（至少一个） | 只在所属池/站点内 |
| **规则 Rule** | "什么条件 → 做什么"（分流/改写/拦截/缓存） | 可选（没有就用站点默认） | 只属于一个站点 |

**关键认知（很多人一开始就搞反）**：
- **源站 ≠ 源站组**。源站=一台真实服务器；源站组=把若干源站打包、定个调度策略（主备/加权），方便复用与回退。
- **建站点不一定先建源站组**。两种回源方式二选一：① 选已有源站组（推荐多站点共用）；② 站点里**直接填源站**（最快上手，对齐 EO「新建站点直接填域名/IP」）。
- **缓存不是本程序自己存的**。它只是个跑在边缘的代码，没硬盘；缓存靠底层平台（`caches.default` 或 `CDN-Cache-Control` 响应头）。你能控制的只是"下什么头、TTL 多少"。

## 0.1 先认识界面

左侧是导航，常用入口：

| 入口 | 干嘛的 |
|---|---|
| **源站池** | 管理「源站组」（一组可互相回退、可负载均衡的源站）。**可选**——站点也能直接填源站，不强制先建它 |
| **站点** | 管理加速域名；回源来源用「选源站组」或「直接填源站」二选一，配规则与安全 |
| **统计** | 看访问量、命中率、源站分布 |
| **系统** | 平台能力探测、配置备份（导出/导入）、密码修改 |
| **流量序列** | 把一个站点（或全部站点）的规则画成流程图，可点击跳转、可拖拽调优先级 |

> 💡 不要再被「必须先建源站池」误导：新建站点时，抽屉里「源站方式」提供两个选项——
> - **选择已有源站组**：复用已建好的池（多站点共用、需要多地址负载均衡时用）。
> - **直接填写源站**：当场填源站地址/端口/协议，无需先去源站池页面建池。对齐 EO「新建站点直接选域名/IP 模式并输入」。

## 1. 方式一（推荐复用）：先建源站组

如果你打算多个站点共用同一组源站，或需要多域名/IP 做负载均衡，先建源站组更省事。点「**源站池** → 新建」。

最小可用配置（把 `example.com` 当源站）：

- **源站组 ID**：系统自动生成（如 `pl_xxx`），**不用你填**——这是给机器/接口引用用的内部主键。
- **名称**（可选，给人区分）：填 `主站源站` 之类即可。
- **调度策略**：`chain`（主源挂了自动切下一个）
- **源站列表** → 添加一条：
  - 地址：`example.com`（**只填 host，别带 https:// 和路径**）
  - 协议：`https`
  - 权重：`1`

点「保存」。列表里会出现这条源站组（显示你填的「名称」，如「主站源站」；背后的 ID 由系统生成，鼠标无需关心）。

> 想加备源？再点「添加源站」，填第二个地址，策略选 `chain` 时它会排在后面，主源失败时自动顶上。

---

## 2. 第二步：建站点

点「**站点** → 新建」。

- **加速域名**：`img.example.com`（这就是用户访问的加速域名；支持 `*.example.com` 泛域名）
- **源站方式**：
  - 选「**选择已有源站组**」→ **默认源站池**选刚才建的源站组（下拉里显示的是你填的「名称」，背后引用的是系统自动生成的 id）；
  - 或选「**直接填写源站**」→ 在下方填写源站地址（如 `example.com`）、端口、协议即可，**无需先建源站组**。
- 其余先默认

点「保存」。

> 两种方式的区别只在「源站组能否被多站点复用」。如果你只有一个站点、只想快点跑起来，选「直接填写源站」最省事。

保存后这条站点会出现在列表。点它进入**站点编辑抽屉**，里面有三大块：**基础设置 / 路由规则 / 安全防护**。

---

## 3. 第三步：配一条规则（把 /images 走缓存）

进站点抽屉 → 切到「**路由规则**」。

点「**添加规则**」，你会看到：

### 3.1 匹配条件（什么时候生效）

两种方式，任选：

- **快捷条件**：路径前缀填 `/images`、扩展名填 `jpg,png`（适合简单场景）。
- **可视化多条件**（推荐，更直观）：点「添加条件组」，选：
  - 匹配对象 `path`，操作符 `prefix`，值 `/images`
  - （可再加一组做「或」关系）

> 不填任何条件 = 匹配所有请求（常用来做「整站兜底」规则）。

### 3.2 动作（做什么）

在同一张卡片里继续填：

- **源站池**：留空 = 用站点默认池；也可以选别的池把这部分流量分流过去。
- **路径重写**：比如访问 `/images/a.png` 实际回源 `/a.png`，选 `strip` + 值 `/images`。
- **强制 HTTPS**：打开，跳转码 `301`。
- **缓存**：打开，「边缘缓存 TTL」填 `3600`（1 小时；Cloudflare 走 `caches.default` API，EdgeOne 走 `CDN-Cache-Control` 响应头委托边缘缓存）。
- **客户端 IP 头**：默认开 `X-EdgeGateway-Client-IP`，源站就能读到真实访客 IP。

填完点「保存规则」。

> 一条规则可以挂**多个动作**（重写 + 缓存 + 改头 同时生效），不用拆成多条。

---

## 4. 第四步：配安全防护

进站点抽屉 → 切到「**安全防护**」。

| 功能 | 怎么开 |
|---|---|
| **防盗链** | 模式选 `whitelist`，域名列表填 `example.com`（允许的来源），「允许空 Referer」按需开 |
| **UA 过滤** | UA 黑名单填常见爬虫/恶意 UA |
| **IP 控制** | 黑名单填要封的 IP/CIDR；白名单填放行的（白名单优先） |
| **签名 URL** | 开启，填 `secret`（密钥），`ttl` 填有效期（秒），`param` 默认 `sign` |
| **限流** | 开启，`rpm` 填单 IP 每分钟上限（如 `60`） |

保存后，命中规则的请求在「回源之前」就被拦下，直接返回对应状态码。

> 想让安全对**所有站点**兜底？去「系统 → 全局配置」设 `security` / `ipWhitelist`。

---

## 5. 验证回源成功

用加速域名访问：

```bash
curl -I https://img.example.com/images/a.png
```

看响应头里有没有这些调试信息（便于你确认链路）：
- `X-Cache`：`HIT`（缓存命中）/ `MISS`（回源）/ `PASS`（不缓存）
- `X-Origin-Addr`：实际回源的源站地址
- `Server: EdgeGateway` / `Via: 1.1 EdgeGateway`：本项目品牌头

---

## 6. 优先级怎么排（很重要）

规则按 **`priority` 从高到低**逐个匹配，**命中第一条就停**。

- 在站点抽屉的「路由规则」里，每条规则卡片右上角能调优先级数字（大 = 先匹配）。
- 想让某条规则先生效 → 把它的优先级调高。
- 也可以直接去「**流量序列**」里**拖拽**规则节点排序（见下）。

## 7. 流量序列（Traffic Sequence）

点左侧「**流量序列**」。这是把请求从进入网关到返回客户端的**真实处理顺序**可视化，采用 Cloudflare 流量序列风格：顺序固定不可更改，**每个环节卡片本身就是一个规则引擎**（或配置入口），点击即可为该环节添加/编辑规则；没有规则的环节为纯只读。

### 7.1 单站点视图

顶部选一个站点，下面是一条竖向流程图，自上而下是请求的真实处理顺序（严格对应 `docs/12-request-flow.md`）：

```
① 匹配站点
②.1 IP 访问规则 → ②.2 WAF → ②.3 Bot → ②.4 Access → ②.5 速率限制
③ 首要分流（选初始源站）
④ URL 重写 → ④ 重定向规则 → ④ 直接响应 → ④ 强制 HTTPS
  → ④ 修改请求头 → ④ Origin Rules → ④ Cache Rules
⑤ 确定实际源站 → ⑥ 合并缓存策略&缓存键 → ⑦ 查边缘缓存
⑧ 回源循环（真正发请求） → ⑨ clone → ⑩ 改写响应头 → ⑪ 写边缘缓存 → ⑫ 返回用户
```

关键认知：和 Cloudflare 一样，**每个阶段卡片都可以设置自己的规则**。后端仍统一存储在 `site.rules` 中，前端按 action 类型把规则分配到对应阶段展示/编辑。一条规则若包含多个 action，可能出现在多个阶段卡片下（数据不分裂）。

- **可干预环节（带规则引擎）**：① 站点、② 安全各包、③ 源站、④ URL 重写 / 重定向 / 直接响应 / 强制 HTTPS / 修改请求头 / Origin Rules / Cache Rules、⑥ cacheGen、⑧ 源站池。
- **纯只读环节**：⑤ 实际源站（推导）、⑦ 查缓存、⑨~⑫ 回源后加工（运行时行为）。
- **拖拽规则节点**：同一阶段卡片下的规则节点可拖拽调整优先级（后端按 priority 降序固化），跨阶段的规则优先级仍由全局 priority 决定。

### 7.2 全部站点总览

顶部选择器选「**全部站点总览（跨域名）」，会列出**每个域名**的序列：每个站点一个分组，头部显示「规则数 / 安全状态 / 源站」，下方是其完整流程。点击分组可跳转到该站点编辑。

> 这个功能对「一整套规则怎么跑」特别直观，强烈建议配完规则都来这里过一眼。

## 8. 配置备份（迁移 / 防丢）

点「**系统 → 配置备份**」：
- **导出**：下载一份完整 JSON 到本地（不外传任何服务器）。
- **导入**：选一份 JSON 整体覆盖当前配置（迁移环境时最省事）。

## 9. 改管理面密码

点「**系统 → 修改密码**」，输入新密码保存即可（仅本地 dev 下首次登录会把 `.dev.vars` 的密码哈希固化进 KV）。

## 10. 常见手滑

| 你想做 | 正确姿势 |
|---|---|
| 源站地址 | 只填 `oss.com`，路径用「路径前缀 / pathPrefix」 |
| 整站兜底规则 | 不填任何匹配条件，动作里设好源站池/缓存 |
| 让 A 路径走源站池 X、其余走默认 | 建两条规则，给 A 的规则更高 `priority` |
| 临时停用一条规则 | 规则卡片里关「启用」，不用删 |
| 看请求到底命中了哪条 | 看响应头 `X-Origin-Addr` + 去「流量序列」核对顺序 |
